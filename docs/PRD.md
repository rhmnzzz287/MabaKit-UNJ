# Product Requirements Document: MabaKit

Revisi v2: 22 Oktober 2026. Target aktif: demo presentasi dosen, bukan toko yang menerima uang nyata. Tujuan bisnis mengikuti [BRD.md](BRD.md); kontrak data mengikuti [SCHEMA.md](SCHEMA.md); keputusan desain di [superpowers/specs/2026-10-22-mabakit-business-website-v2-design.md](superpowers/specs/2026-10-22-mabakit-business-website-v2-design.md).

## 1. Tujuan dan scope aktif

Website toko perlengkapan PKKMB mahasiswa baru UNJ, wali dan koordinator. Pembeli menjelajah katalog, memilih paket sesuai fakultas atau barang satuan, login, checkout, melakukan simulasi pembayaran, lalu memantau pesanan dan invoice digital lewat akun. MabaKit menjual barang sendiri, bukan marketplace atau kanal resmi kampus.

Paket adalah penawaran utama; satuan tetap dapat dibeli pada bagian tersendiri. Kustomisasi berarti penyesuaian isi dan varian paket terhadap fakultas, dihitung server. Editor bebas warna, teks, bordir, atau tambah/hapus komponen bukan bagian produk.

Platform: React + TypeScript + Vite + Tailwind CSS di Cloudflare Workers Static Assets, API Cloudflare Workers dan database D1. Gambar katalog diekstrak dari `docs/reference/updatekatalog.pdf` (fallback `docs/reference/katalog.pdf`) melalui manifest; R2 ditunda sampai upload diperlukan.

Booking/reservasi tidak masuk produk maupun roadmap. Tidak ada kalender, pilihan slot, kuota kunjungan, booking fee atau reschedule. Pengambilan mengikuti informasi toko setelah READY, tanpa memesan waktu. Alokasi stok checkout adalah pengaman internal, bukan reservasi pelanggan.

Midtrans/Xendit ditunda sampai pemilik memutuskan melanjutkan setelah presentasi. Demo tidak meminta kredensial merchant, mengirim request gateway, menampilkan QR/rekening pembayaran nyata atau menerima uang. Kurir tampil nonaktif bertuliskan `Segera tersedia`, tanpa alamat kirim, ongkir atau resi. QR pickup, pengiriman email otomatis, PDF otomatis, diskon kelompok otomatis, kupon dan scanner kamera ditunda. Diskon persen manual per produk dan pesanan gratis 100% termasuk lingkup demo.

## 3. Uang dan snapshot

Semua nominal INTEGER rupiah, operasi JavaScript memakai safe integer, bukan pecahan float untuk uang. Harga SKU/paket positif; subtotal = jumlah unit_price_rp × quantity; total = subtotal. Pickup dan biaya simulasi Rp0, tidak ada surcharge tersembunyi.

Harga paket mengikuti harga server yang ditetapkan admin untuk konfigurasi fakultas. Rincian isi dan total ditampilkan; klaim `hemat Rp...` hanya bila selisih terhadap total satuan benar dan positif.

Fixture SIMULASI: A Rp15.000 × 2 + P Rp30.000 × 1 = Rp60.000. Jika P berisi A×1/B×2, kebutuhan stok A×3/B×2. Paket tidak mempunyai stok virtual kedua. Snapshot judul, atribut, komponen, harga, fakultas dan instruksi tidak berubah setelah checkout; edit profil atau katalog tidak mengubah order lama.

## 4. Status dan pembatasan simulasi

| Dimensi | Status demo | Aturan |
|---|---|---|
| payment_status | PENDING, PAID, EXPIRED | PAID hanya melalui endpoint percobaan milik akun; semua row payment mode DEMO |
| fulfillment_status | UNFULFILLED, READY, PICKED_UP, CANCELLED | READY perlu PAID; penyerahan sekali; expiry membatalkan draft |
| stock_allocation_status | HELD, CONSUMED, RELEASED | HELD dikonsumsi saat PAID atau dilepas saat expiry; tidak kembali HELD |

Endpoint konfirmasi simulasi hanya terdaftar saat environment demo eksplisit. Deployment produksi tidak boleh mendaftarkannya; request harus ditolak. Mengubah label atau environment saja tidak mengaktifkan gateway nyata. Data DEMO tidak boleh disalin menjadi transaksi produksi atau diperlakukan sebagai pembayaran sah. Nilai di dashboard diberi konteks `Transaksi percobaan`.

Reset demo harus dibatasi operator, menolak environment non-demo dan tidak pernah menyentuh database produksi. Reset bukan fitur publik.

## 5. Keamanan dan kualitas

Semua akses D1 melalui Worker. Tidak ada RLS atau akses DB langsung dari browser. Actor dari sesi server, otorisasi/ownership per route, SQL berparameter, projection field minimum. Password di-hash dengan Web Crypto PBKDF2-SHA256 bergaram; cookie sesi opaque HttpOnly/Secure/SameSite, token disimpan sebagai hash; mutasi memeriksa Origin dan token CSRF. Logout dan pencabutan segera menolak request berikutnya. Cookie pembeli (`mbk_sess`, `mbk_csrf`) dan operator (`mbk_op_sess`, `mbk_op_csrf`) terpisah; role dan izin selalu dibaca ulang dari D1 per request. Rate limit checkout 5/menit/akun serta percobaan login per sumber dan per identitas harus ditegakkan server, bukan hanya memory per instance.

Batas awal pilot: maksimum 2 draft HELD aktif per akun dan 10 per IP hash; penolakan 429 tanpa alokasi baru. Counter dan pemeriksaan hold harus atomik di D1, termasuk request paralel; IP bersama bisa terkena limit dan operator dapat meninjau batas tanpa menonaktifkan proteksi. Jangan menyimpan IP mentah; hash/window kedaluwarsa dibersihkan. Uji bypass lewat akun baru wajib sebelum demo publik.

Cookie sesi tidak disimpan di localStorage. Token hanya hash di DB; tidak ada token pickup atau QR pada alur demo. Respons error tidak membocorkan SQL, token atau PII. HTTPS, CSP, rendering teks tanpa HTML mentah dan secret binding wajib. Demo publik tetap memakai data fiktif, akses minimum dan isolasi environment. Kredensial seed presentasi (`mabakita@admin` / `admin123`, `tim@demo.mabakit` / `staffmabakit123`, `pembeli@demo.mabakit` / `buyermabakit123`) hanya untuk lingkungan presentasi terisolasi, tidak ditampilkan di storefront, dan diganti sebelum penggunaan operasional. Tidak ada alur reset password lewat email pada demo.

Mobile mulai 360px, zoom 200%, target 48px, keyboard, focus, reduced motion dan kontras WCAG AA. Status loading/empty/error dan retry wajib; tidak perlu polling gateway pada demo. Target uji, bukan klaim hasil: LCP ≤2,5 detik, CLS ≤0,1 pada profil mobile 4G; checkout server p95 ≤2 detik; pilot 20 checkout serentak.

## 6. Gerbang pembayaran nyata, ditunda

Jangan membuat adapter Midtrans/Xendit, webhook atau cron rekonsiliasi sekarang. Sebelum aktivasi: pilih satu provider, setujui D01-D08, hardening autentikasi produksi/MFA/recovery, kebijakan refund/retensi, biaya cloud dan backup. Kontrak provider ditulis dan diuji sandbox sebelum kode menerima uang.

Baseline keamanan kelak: total server, signature dan status provider diverifikasi, amount/currency/referensi/environment cocok, idempotency, jaringan di luar batch D1, timeout tidak melepas stok ambigu. Late settlement setelah release masuk REVIEW/CANCELLED, bukan menghidupkan order. Refund penuh manual dengan bukti; restock sekali sebelum pickup, tanpa restock otomatis setelah penyerahan. Detail status live dan mapping provider merupakan pekerjaan baru, bukan fitur demo yang telah selesai.
